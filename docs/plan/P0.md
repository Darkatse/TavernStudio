# Studio P0：运行时验证

> 目标：用真实 vendor 验证[运行时架构](../Architecture.md#4-运行时)，凭数据给每项风险下结论，并把结论回写到架构文档。P0 阶段不做界面打磨。

**先参考，后动手。** 每项开工前，先读 [References](../References.md) 中已有实现的做法，再决定沿用还是不同：
- V2、V3：PureTavern 的 Legacy Hook 与 Service Worker；TT 的拦截器与协议层。
- V4：TT 的 Rust repositories（`tt-adapter-storage-core`）与 FrontendHostContract。
- V5、V6：JSR 的 iframe 运行时；TT 应用内助手对 app-use 的接入。
- V10：ST、TT、JSR 各自写入浏览器端状态的代码。

## S0 仓库骨架

> 状态：已完成。

- pnpm workspace，许可 AGPL-3.0。目前只有 `apps/studio`；[Architecture §8](../Architecture.md#8-技术栈与仓库) 中的其余目录，在第一项用到它的工作开工时建立，不预建空包。
- 工具链见 Architecture §8。Rstest 随第一个测试一起加入。
- 界面基础：[UI](../UI.md) 的 token、动效档位与基础组件；工作区外壳，包括 Agent 栏、工作台、预览与代码标签、设备舞台和窄屏布局。
- 架构文档迁入 `docs/`；`AGENTS.md` 写明"先参考，后设计"。
- 检查入口只有一个：`pnpm run check`。CI 在推送到 `main` 和 PR 时运行它。

## 验证项

> 状态：进行中。V4 等 TauriTavern 改正 W1 的扩展发现，V6 的点击等 app-use 0.1.1，V10 的 TT 部分随 V4；其余项的结果与测量见 [P0 报告](P0-Report.md)。

| # | 验证内容 | 通过标准 |
|---|---|---|
| V1 | ST 镜像构建：npm `sillytavern@1.19.0` → 预构建 `lib.js` → 锚点注入 → 生成 hash 清单 | 锚点不唯一时构建失败 |
| V2 | Preview SW：区分 iframe 导航与顶层导航、映射 vendor 文件、从 Cache Storage 提供子资源、对 `/api/*` 返回 501、未命中返回真 404 | 冷启动和热重载时页面都由 SW 控制 |
| V3 | Session Backend 启动所需端点 + ST 接入（含同步 XHR 与子 iframe）+ showcase 样板 | ST 启动并渲染出聊天，控制台没有未被接管的请求 |
| V4 | TT 镜像经 Web Host（T4 W1 分支）启动 | 桌面和移动两种身份都能渲染出聊天 |
| V5 | 从上游安装 JSR，前端卡在 srcdoc iframe 中渲染 | iframe 内对 `/scripts/extensions/third-party/JS-Slash-Runner/...` 的请求由 SW 应答；分别记录 Chrome、Edge、Firefox、Safari 的结果 |
| V6 | 把 npm 上的 `@tauritavern/app-use@0.1.0` 注入预览页面 | `app.snapshot` 能进入 JSR iframe，`app.interact` 能完成一次点击 |
| V7 | 截图方式：snapdom 与 Element Capture | 在模糊主题和 JSR iframe 上对比两者的保真度与耗时，选定默认方式 |
| V8 | 通过 ST 自己的控件热应用主题 | 写 `#customCSS` 和设置取色器两条路径都生效，结果与重载后一致 |
| V9 | `window.top` 的影响范围 | LittleWhiteBox 等样本的实际表现记录在案 |
| V10 | 浏览器端状态：盘点 ST 1.19.0、TT 镜像与 JSR 写入的键和数据库；切换镜像时清理；数据子资源带 ETag | 清理后源上只剩 Studio 自有存储，不会卡在删除数据库；替换同名背景后，TT 的缩略图随之更新 |
| V11 | 运行时诊断：分别在扩展脚本、JSR 脚本、前端卡 srcdoc 中制造语法错误和运行时错误 | 全部被捕获并映射回项目文件；独立文件的行号准确，内联脚本记录实际精度 |

## 测量

- ST 与 TT 的冷启动时间、热重载时间、首屏传输量；
- 热应用延迟；
- 两种截图方式的耗时。

- V1–V8、V10、V11 通过，V9 记录在案；未通过的项需给出有证据支撑的替代方案，并同步更新架构文档和 Decisions。
- 测量结果写入 `plan/P0-Report.md`，用于确定 P1 的性能预算。
