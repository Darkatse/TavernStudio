## 设计要点

### 1. 数据路径

以下几处使用同一种路径，即相对数据根的路径，例如 `default-user/settings.json`、`_css/user.css`：Mount 的 `to`、Session、Preview SW、样板。

### 2. Mount

- **挂载点**：一条 Mount 的目标，由数据路径加可选的 JSON Pointer 组成。
- **指向生效态**：Mount 挂到 vendor 启动时读取的那份数据。
  - ST 启动时只从 `settings.json` 读取外观。主题文件只有在下拉框里被选中时，才由 `applyTheme` 把字段逐个复制进 `power_user`。
  - 因此主题挂到 `settings.json#/power_user`，不挂到 `themes/<名>.json`。挂到主题文件时，重载后看不到主题，"重载是权威"就不成立。
  - 预设作用域的正则和脚本同理，挂到 `settings.json` 里当前预设的副本。
- **合并**：
  - JSON 挂到 Pointer 时，按 JSON Merge Patch（RFC 7386）合并：对象按键覆盖，其余值整体替换。
  - 文本挂到 Pointer 时，成为该位置的字符串值。
  - 不带 Pointer 时，整个文件替换。
  - 两条 Mount 写到同一个位置时报错，不按先后顺序覆盖。
- **所有权**：项目只拥有它写出的键。采纳和导出都只看这些键。
- **结构化文档**：Pointer 可以指向 JSON 文件，也可以指向角色卡 PNG 里嵌的卡片 JSON。后者的读写规则与 ST 相同。
- **目录**：`from` 可以是目录，整棵子树原样挂到 `to` 下。扩展通常写两条 Mount：一条挂 `manifest.json`，一条挂 `dist/`。这样保留了扩展根的布局，manifest 里的路径和相对 import 都依赖这个布局。
- **`fence`**：先把文本包成 Markdown 代码块再挂载，例如 `"fence": "html"`。
  - 生态里的前端代码都以代码块的形式出现在消息文本里，例如正则的 `replaceString`、`first_mes`、世界书。酒馆助手也只把含 HTML 的代码块渲染成前端卡。
  - 无构建和本地文件夹两档都走这一条路。
  - 包装后行号只差固定的一行。
- **反向写回**：采纳时沿同一条 Mount 反向写回。
  - JSON 写回项目文件里对应的键；
  - 文本写回整个文件；
  - 带 `fence` 的先去掉包装。

主题模板：

```json
{
  "fixture": "showcase",
  "mounts": [
    { "from": "theme.json", "to": "default-user/settings.json#/power_user" },
    { "from": "theme.css", "to": "default-user/settings.json#/power_user/custom_css" }
  ]
}
```

- `theme.json` 存放 `power_user` 中属于主题外观的字段。选中的主题名 `power_user.theme` 与 `reduced_motion` 属于用户，项目不拥有，理由见 [Architecture §6](../Architecture.md#6-项目)。
- 导出时照 ST 的 `getThemeObject` 组装：`name` 取项目名，其余字段取项目拥有的键。

已知限制：Pointer 里带数组下标时（如 `…/scripts/0/content`），作者在 ST 界面里调整顺序后就会错位。P1 接受这一点，采纳界面把它显示为整体差异。

### 3. 项目改动怎样到达预览

- **写入**：项目文件变化后，重新计算受影响的 Mount，按挂载点写入 Session 当前的数据，再发布到 Cache Storage。
  - 只替换挂载点上的内容。Session 里的其他写入照常保留，例如聊天、变量和设置。
- **分派**：热应用按数据路径（包括 Pointer）分派，不按项目类型分派。
  - 没有热应用入口的路径，就重载 View。
  - 分派表在各切片中逐项实测，每一项都与重载结果对照，然后写进 Architecture §5。
- **vendor 在内存里持有的数据**：如果 vendor 在内存里持有一份数据、保存时整体写回，那么只改 Session 不会生效，之后 vendor 保存时还会用旧值把它覆盖。
  - 这类路径只能走 vendor 的公开入口，做不到就重载。
  - 目前已知的有：`settings.json` 的全部字段、酒馆助手脚本、世界书、Quick Reply。
- **修正 Architecture §5 的两处事实**：
  - 取色器只需设置 `color` 属性，它会自己派发带 `detail.rgba` 的 `change`。如果再手动派发一次，ST 的处理器会抛错。
  - 扩展 CSS 的 `<link>` id 是 `third-party_<name>-css`。热应用时原位替换 href，不重新插入，以保持层叠顺序。
- **重载也改变不了的内容**：预览如实呈现这些情况，与真实 ST 一致。
  - 已有聊天里的开场白：`first_mes` 只在新建聊天时复制进聊天。
  - 已经被输出正则改写过的消息。

### 4. 会话写入与采纳

- **回声写入**：项目拥有的键上，内容与 Snapshot 语义相等的会话写入。回声不显示为差异。例如：
  - 热应用之后 vendor 自己的回写；
  - ST 每次启动都会整份重写 `settings.json`。
- **比较**：按挂载的语义比较。
  - JSON 解析后，比较项目拥有的键；
  - 文本逐字比较；
  - 角色卡比较里面嵌的 JSON；
  - 带 `fence` 的先去掉包装再比较。
- **vendor 的规范化**：例如把颜色统一写成 `rgba(r, g, b, a)`。这类差异如实显示，作者采纳一次后，项目就与 vendor 的写法一致了。
- **采纳粒度**：以挂载点为单位，不提供按代码块采纳，因为只采纳一部分可能写出无效的 JSON。
- **冲突**：项目改动会覆盖同一挂载点上尚未采纳的会话写入。被覆盖的内容要显式提示，不静默丢弃。

### 5. Session 持久化与标签页接管

- **持久化的内容**：Snapshot 标识、相对 Snapshot 的写入覆盖层、Web Host 文档，都存进 IndexedDB。
  - 以内存为准。持久化在后台按写入顺序进行，不挡住同步应答。
- **持久化失败**：报诊断，界面标明 Session 未持久化。不能降级为只存内存、却照常回报成功。
- **重新打开 Studio**：由样板和项目合成 Snapshot，再叠加覆盖层。如果期间项目改过某些挂载点，按 §3 用项目的内容覆盖。
- **重置 Session**：丢弃覆盖层。
- **标签页接管**：Session 由一个 Web Lock 持有。
  1. 新标签页经 BroadcastChannel 请求接管。
  2. 旧标签页卸载 View（TT 先经 `exit()` 保存），等持久化写完，然后释放锁，并显示"已在另一个标签页打开"。
  3. 如果 5 s 内锁没有释放，新标签页直接抢占锁，并在诊断中报告可能丢失的写入。
  
  这与 View 的卸载是同一个模式。

### 6. 项目存储

- **两种来源，一种实现**：项目放在 OPFS 里；本地文件夹经 File System Access 打开。两者都是 `FileSystemDirectoryHandle`，所以工作区只需要一种实现。
  - 目录句柄存在 IndexedDB 里，打开项目时重新请求授权。
- **本地文件夹会被外部构建改写**：
  - 变化通知先测试 `FileSystemObserver` 是否可用，不可用时改为轮询；
  - 按一次构建去抖；
  - 读到不完整的产物时报错并重读，不沿用旧值。
- **CAS**：工作区的 CAS 检查和写入放在同一个异步互斥区里完成，对应 TT 的写锁。
- **备份**：项目归档为 zip，格式与导入时的路径检查见 [Architecture §6](../Architecture.md#6-项目)。

### 7. Agent

- **Run**：对标 TT 应用内助手的 Session 模式。
  - 模型给出不带工具调用的回复，Run 即结束，不设 finish 工具。
  - 取消不回滚。
  - 刷新页面后，缺少终态的 Run 显示为 interrupted。没有收到结果的工具调用，按 TT 的文案改写为一条说明，工具不重放。
  - Guidance 在下一轮请求模型之前加入上下文。
- **History 与 Journal**：
  - History 是规范的消息记录，每条带上所在的 Round。Transcript 和发给模型的上下文都由它得出。
  - Journal 只记录进度、终态和大结果的引用。
- **工作区工具**：规则和错误码照搬 TT。
  - 读状态加 CAS，先读后改；
  - 只读过部分内容时，对补丁的限制；
  - `read_file` 的输出格式与读取上限；
  - 参数规范化；
  - 长结果写入 `tool-results/`。
- **工具名**：
  - 稳定 ID 用点分组，发给模型时把点换成下划线，与 TT 同一规则。
  - 编辑工具叫 `workspace.edit_file`，与 TT 的 `apply_patch` 语义相同。不沿用 `apply_patch` 这个名字，因为它是 GPT 系模型在 Codex 中训练的补丁格式的名字。
  - Skill 里不写工具名。
- **Checkpoint**：
  - Run 第一次写某个文件之前，先保存它原来的内容，保存完成后才写入。Run 新建的文件也记录下来，回滚时删除。
  - 保存与 CAS 检查共用同一次读取，不额外读文件。
  - 内容按 SHA-256 去重，用浏览器自带的 `CompressionStream`（gzip）压缩后存进 IndexedDB。
  - 总量有上限，默认 100 MB。超出时从最旧的 Run 开始清理，并删除不再被引用的内容。被清理的 Run 在界面上标明不能回滚，不静默失效。
  - 回滚前先核对，文件仍是该 Run 写下的内容；不是的话，列出冲突。
  - 回滚记为一条新的 Journal 事件。之后的 Run 保留并标注"已回滚"，回滚本身也可以撤销。
  - TT 的 checkpoint 指执行状态，与这里同名不同义，在 Agent.md 中注明。
- **截图**：截图作为工具结果里的图片返回；OpenAI 兼容接口只接受 user 消息里的图片，由 pi-ai 移过去（[Agent §2](../Agent.md#2-模型接入)）。上下文只保留最近 3 张。取得方式见 [Agent §5](../Agent.md#5-视觉)。TT 没有这方面的先例。
- **Run 的大件存储**：截图和写入 `tool-results/` 的长结果占用最大。
  - 只保留最近 20 个 Run 的这类内容。
  - 更早的 Run 在 Transcript 里显示为"已清理"。
  - History 和 Journal 的文字记录保留。
- **存储占用**：设置中显示 Agent 存储的占用（`navigator.storage.estimate()`）。上限与保留数的默认值在 P1a 实测后调整。
- **模型接入**：用 pi-ai 的单轮流式接口，见 [Agent §2](../Agent.md#2-模型接入) 与 Decisions。比较过 AI SDK 7 与 TanStack AI 之后选它，决定性的一项是签名与加密推理能原样回放。沿用 TT 模型网关的经验：
  - 停止原因为 length 时不执行工具；
  - 模型调用了未声明的工具时，Run 失败；
  - assistant 消息原样保存、原样回放；
  - callId 可能重复，按顺序配对。
  
  中转端点是否回传 reasoning 字段，逐个实测。

### 8. 样板

- **内置样板**只读，共三份：showcase、MVU 卡、200 楼长聊天（见 [Performance §8](../Performance.md#8-分期与待验证)）。
  - 样板要预先启用酒馆助手对其角色和预设的开关，并关闭"实时监听"。否则一启动就会弹窗、产生写入，或与热应用同时重载。
- **导入**：
  - 以一份内置样板为底，加入作者自己的角色卡（PNG 或 JSON）、聊天 JSONL、主题和世界书，存为用户样板。用户样板的格式与内置样板相同。
  - 导入语义沿用 ST 的原生端点。格式不对时立即失败，并说明原因。
  - 样板编辑器属于 P2。

### 9. 导出

- **组装**：按 Mount 读取合成后的数据，组装为 ST 能导入的格式：主题 JSON、角色卡 PNG、Script.json、正则 JSON、世界书 JSON、Quick Reply JSON、`user.css`、扩展 zip。
- **保存**：用户点击后才打开保存位置的选择器。结果区分"已保存"和"已交给浏览器下载"两种。
- **本地文件夹模式**：导出的是 `dist/` 里现有的产物，界面上写明这一点。watch 产出的是开发构建，发布构建由作者自己负责。

### 10. 知识

- **解剖图**随镜像构建一起生成。
  - P1a 先生成主题需要的部分：CSS 变量、控件 id、DOM 地标。
  - P1b 补上 `getContext()` 的键、事件和 API 索引。酒馆助手的 `@types` 不在镜像里，收进知识包的 `knowledge/jsr/`。
- **Skill**：首批六个由 Studio 自己编写。
  - StageDog 模板的 Skill 和 AGENTS.md 采用 PolyForm Noncommercial 许可，原文收进 `knowledge/`，附上许可原文与出处。
  - 不改写进 Studio 自己的 Skill，这是 Studio 的取舍，见 [Knowledge §4](../Knowledge.md#4-许可)。
- **知识包**：已建成。`pnpm knowledge` 按 `knowledge/sources.mjs` 生成八个来源的分片，随 Studio 发布在 `/_studio/knowledge/`，Agent 从只读的 `knowledge/` 读取。CI 定时更新放到 P2。

## 切片

每个切片以一个作者场景收尾。场景脚本沿用 P0 的 playwright 框架（`scripts/lib/studio.mjs`）。

### P1a 主题

**场景**：
1. 从主题模板新建项目；
2. Agent 修改配色和 CSS；
3. 预览热应用；
4. Agent 截图自查；
5. 作者在 ST 界面里微调后采纳；
6. 导出主题 JSON，经 ST 自己的导入流程导入并选中后，与预览一致。

ST 和 TT 都要通过。

**架构**
- `packages/workspace`：项目存储、Mount 的合成与反向写回（§2 的全部语义）、Snapshot 增量。Mount 在这一切片一次做完整，后续切片只做接入。
- Session 持久化与标签页接管。
- 主题热应用：控件 id 取自解剖图。会话写入的采纳。
- `packages/agent`：Run 循环、History、Journal、Checkpoint、BYOK；`workspace.*`、`preview.*`、`app.*` 三组工具。
- 解剖图的主题部分、`st-theme` Skill、主题导出、项目归档。
- 已实测：`power_user.theme` 指向的主题不在主题库里时，ST 不报错，TT 启动时报"主题不可用"并改用另一个主题，覆盖项目的外观。结论是项目不拥有这个键，样板不必提供主题库条目，见 [Architecture §6](../Architecture.md#6-项目) 的所有权。

**界面**：Transcript、Composer、Checkpoint、文件树与编辑器外框、采纳面板、设置（BYOK、深浅色）、新建与打开项目、Toast 与确认对话框。中文正文和 Transcript 的字号在这一切片实测后定稿。

**性能**：外壳首屏、编辑到预览可见、主题热应用、持久化不阻塞、Transcript 流式输出与长 Transcript。另外测清 TT 重载比 W1 多出的 0.3 s 花在哪里。

**已交付**：上述架构、界面与性能项。场景脚本 `scripts/p1/theme.mjs` 在 ST 与 TT 上通过；正文字号保留 14/23。界面说中文和英文（[UI §6](../UI.md#6-文案与本地化)）；设置分"通用"（深浅色、语言、存储占用）与"模型"两页。待维护者看录屏审阅。

### P1b 卡片与脚本

**场景**：
1. 在 MVU 样板上编写状态栏（正则美化加前端卡）和酒馆助手脚本；
2. 用 Replay 推动剧情；
3. 在变量面板里改值，卡片随之更新；
4. 运行时报错定位到源码行；
5. 导出角色卡、正则与脚本。

**架构**
- **热应用逐项实测**：
  - 角色卡字段：`getCharacters()` 加 `reloadCurrentChat()`；
  - 酒馆助手脚本：`replaceScriptTrees`，它只作用于当前角色或预设；
  - 全局正则与角色正则；
  - 世界书：先清缓存，再刷新编辑器；
  - Quick Reply：`quickReplyApi`，或者重载。
  - 前端卡写在 `first_mes` 里时，需要提供一个新建聊天的入口。
- **Session Backend** 补上 `/api/presets/save`。
- **srcdoc 行号换算**：
  - 脚本 iframe 以 `<script type="module">` 之后为第 1 行，前端卡 iframe 以 `<body>` 之后为第 1 行；
  - 再经代码块与 `fence` 换算回项目文件的行号；
  - 锚点在 srcdoc 里查找，不写死偏移量。
- **变量面板**：
  - 调用页内的 `TavernHelper` 变量 API；需要时用 `refreshOneMessage` 重渲该楼，与酒馆助手自带的变量管理器一致。
  - MVU 用 `Mvu.getMvuData` 和 `replaceMvuData`。
  - 不伪造事件。完整的 MVU 事件链用 Replay 复现。
- **样板**：MVU 卡、200 楼长聊天。
- **导出**：角色卡 PNG、Script.json、正则 JSON、世界书 JSON、Quick Reply JSON。

## 界面

界面与架构同等重要。每个切片的界面在开工前先查 [References](../References.md#界面与动效)，交互与动效按 [UI](../UI.md) 规定的档位实现。

**开工前补进 UI.md 的规则**（P1a 开工之前完成）：
1. **折叠**：
   - 高度瞬间变化；
   - 内容用透明度动画，可以加 −4px 的位移，moderate 档进入、fast 档退出；
   - Transcript 和文件树里不对高度做动画。
2. **diff 配色**：
   - 新增 `--color-diff-add`、`--color-diff-del` 两组底色与前景色，低彩度，与 danger 区分开；
   - +/− 符号与删除线同时出现。
3. **循环动画**：只允许 spin 与 indeterminate。不用 shimmer，因为它动画的是 `background-position`。
4. **排版**：
   - 语法高亮的 token；
   - Transcript 与 Markdown 的字号和行高，实测 14/22 与 13/20 两种方案；
   - 中文段落的行高不低于 1.6。
5. **状态**：运行中、已取消、失败、interrupted 四种状态只用 foreground、muted、danger 三种颜色，并配上图标和文字，不只靠颜色区分。
6. **加载、空状态与错误**：
   - 短于 300 ms 的加载不显示提示；
   - 内容形状已知时，用静态骨架；时长未知时，用 indeterminate 细线；
   - 空状态写明下一步该做什么；
   - 错误在原处显示原文，并提供重试。
7. **图标交换**：
   - 两个图标放在同一格，进入用完整档、离开用退出档；
   - 只在 hover 时出现的操作，在触屏和键盘焦点下也必须可见。
8. **尚无规则的部件**：
   - 破坏性按钮；
   - 编辑器的文件标签；
   - Studio 画在预览上的标记，例如 Agent 光标和检查器的选框。它们用 Studio 的强调色，因为作者的主题可能正被改坏；
   - 手动选择深浅色时，偏好怎样在首帧之前读到。
9. **现有偏离**：SegmentedControl 的滑块和 Tabs 的指示条现在对 width 做动画。
   - 它们是绝对定位的小元素，重排只涉及自身；圆角和阴影又没法用缩放表达。这与 Base UI 的 Tabs 指示条做法相同。
   - P1a 用 Performance 面板实测它们每帧的 Layout 开销。开销可以忽略时，在 UI.md 里写明这一例外及其理由；否则改用只在合成层上运行的做法。

**各界面的要点**

| 界面 | 要点 | 来源 |
|---|---|---|
| Transcript | 结构取自 TT：按 Run 分组；RunBar 显示计时和调用次数；只展开最新的 Run；连续的调用合并显示。工具行用现在进行时的文字（如"正在读取 theme.css"），把状态写进文字里。思考过程默认收起，只在跟随底部、且用户没有手动展开或收起过时，才自动开合。流式文本直接追加真实的 token：在 rAF 中合并，已完成的块不再重渲，末尾显示实心光标。跟随底部；提供"回到最新"；加载更早的内容时保持滚动锚点 | 自建；部件改写自 shadcn 的 Trace、Marker |

**组件取用**：
- 按 UI.md §2 的顺序取用组件。
- Fluid Functionalism 和 beUI 的组件依赖 Motion，取用时把动效改写为 CSS 档位。
- 不引入 cmdk 和 `@shadcn/react`。
- 新依赖（headless-tree、`@codemirror/merge`）在开工时核对许可与体积。

**界面验收**（每个切片都做）：
- **深浅色**：新界面在"跟随系统""浅色""深色"三种设置下逐一核对；切换深浅色时，没有逐个元素的颜色渐变。
- **窄屏**（375×812）：切换面板后状态保持；没有横向滚动；触控目标不小于 36px。
- **减少动态效果**：开启后没有位移和缩放；淡入淡出保留；indeterminate 停止。
- **动效与 token**：只用 `motion-*` 档位，退出比进入快；不对 width、height、top、left 做过渡；组件里没有裸值。
- **键盘**：能完成全部操作；焦点环只在 `:focus-visible` 时出现；对话框关闭后，焦点回到触发它的元素；Esc 关闭浮层、退出检查器。
- **流式输出不重排**：
  - 已输出的行不会重新折行；
  - 计时器的宽度不跳动；
  - 回复落成 History 记录时，DOM 不重新挂载；
  - 用户向上阅读时，视口不会被新内容拉走。
- **无障碍**：Transcript 使用 `role=log`，每个 Run 结束时只播报一次；muted 文本、diff 底色上的文本，对比度都不低于 4.5:1。
- **预览**：任何操作都不让 iframe 做尺寸插值；检查器不往 vendor 的 DOM 里插入节点。
- **失败可见**：断网、CORS 错误、OPFS 或目录授权被拒绝时，都有说明原因的错误状态。
- **审阅**：维护者看过录屏后才算通过。录屏覆盖浅色与深色、桌面与窄屏。
